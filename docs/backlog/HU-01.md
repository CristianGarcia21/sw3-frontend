# HU-01 · Registrar incidente o solicitud

**Como** solicitante, **quiero** registrar un incidente o una solicitud de servicio tecnológico, **para** pedir atención a la mesa de servicios.

| Campo | Valor |
|---|---|
| Tipo de caso relacionado | Incidente y Solicitud de servicio |
| Área / Categoría | Todas |
| Prioridad | P1 |
| Story Points | 5 |
| Sprint | 1 |
| Dependencias | Ninguna. Es la base de las demás (necesita modelo de datos y seed de áreas/categorías) |

## Reglas de negocio
RN-01, RN-02, RN-03, RN-04, RN-05, RN-06, RN-07, RN-17 (evento `CREACION`).

1. Tipo, área, categoría, título, descripción y prioridad son obligatorios.
2. Al elegir un área, el selector de categoría solo muestra las categorías activas de esa área.
3. La descripción debe tener mínimo 10 caracteres.
4. La fecha de creación y el estado `Pendiente` los pone el sistema.

## Criterios de aceptación
- **Escenario 1: registro válido.** Given un solicitante de prueba seleccionado, When llena todos los campos correctamente y guarda, Then se genera un ID, el caso queda en `Pendiente` y aparece en la bandeja.
- **Escenario 2: persistencia.** Given un caso registrado, When se reinicia el backend, Then el caso sigue apareciendo con los mismos datos.
- **Escenario 3: sin descripción.** Given el formulario, When la descripción está vacía o tiene menos de 10 caracteres, Then el sistema no guarda y muestra el error en el campo.
- **Escenario 4: categoría de otra área.** Given una petición con una categoría que no pertenece al área elegida, When se envía a la API, Then responde 400/409 y no se crea el caso.
- **Escenario 5: solicitud de servicio.** Given el tipo `Solicitud de servicio`, When se guarda, Then el caso queda almacenado con ese tipo.
