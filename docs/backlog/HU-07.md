# HU-07 · Aprobar o devolver una solución

**Como** validador, **quiero** aprobar o devolver una solución, **para** controlar la calidad de la atención.

| Campo | Valor |
|---|---|
| Tipo de caso relacionado | Incidente y Solicitud de servicio |

| Prioridad | P1 |
| Story Points | 5 |
| Sprint | 2 |
| Dependencias | HU-06 |

## Reglas de negocio
RN-14, RN-15, RN-16, RN-17.

1. Solo usuarios con rol Validador pueden validar, y solo casos `En validación`.
2. Aprobar pasa el caso a `Cerrada` y guarda `fecha_cierre`.
3. Devolver exige un comentario de mínimo 10 caracteres y pasa el caso a `En atención` con el mismo agente.
4. El validador no puede ser quien atendió el caso.
5. Se crea el evento `APROBACION` o `DEVOLUCION` (con el comentario) en el historial.

## Criterios de aceptación
- **Escenario 1: aprobar.** Given un caso `En validación`, When Sofía (validadora) aprueba, Then el caso queda `Cerrada` con fecha de cierre y el evento en el historial.
- **Escenario 2: devolver.** Given un caso `En validación`, When Sofía lo devuelve con el comentario "Sigue sin conexión en el aula 204", Then vuelve a `En atención` y el historial guarda el comentario.
- **Escenario 3: devolver sin comentario.** Given un caso `En validación`, When se devuelve sin comentario, Then el sistema lo rechaza.
- **Escenario 4: bandeja de validación.** Given hay casos `En validación`, When el validador entra a su bandeja, Then ve esos casos con la solución vigente.
