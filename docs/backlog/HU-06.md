# HU-06 · Registrar diagnóstico y solución

**Como** agente, **quiero** registrar el diagnóstico y la solución, **para** documentar la atención que di.

| Campo | Valor |
|---|---|
| Tipo de caso relacionado | Incidente y Solicitud de servicio |
| Área / Categoría | Todas |
| Prioridad | P1 |
| Story Points | 5 |
| Sprint | 2 |
| Dependencias | HU-04, HU-05 |

## Reglas de negocio
RN-12, RN-13, RN-17.

1. Solo el agente asignado puede registrar atención, y solo con el caso `En atención`.
2. Diagnóstico y solución son obligatorios, mínimo 10 caracteres cada uno.
3. Un caso puede tener varias atenciones (si lo devuelven). La vigente es la más reciente.
4. Después de registrar la solución el agente puede enviar el caso a `En validación`.
5. Se crea el evento `ATENCION` en el historial.

## Criterios de aceptación
- **Escenario 1: registrar atención.** Given un caso `En atención` asignado a Andrés, When Andrés registra diagnóstico y solución, Then la atención queda guardada con fecha y agente.
- **Escenario 2: otro agente.** Given un caso asignado a Andrés, When Marta intenta registrar la atención, Then el sistema responde 403.
- **Escenario 3: enviar a validación sin solución.** Given un caso `En atención` sin atenciones, When se intenta pasar a `En validación`, Then el sistema lo impide.
- **Escenario 4: enviar a validación.** Given un caso con solución registrada, When el agente lo envía a validación, Then pasa a `En validación` y queda en el historial.
